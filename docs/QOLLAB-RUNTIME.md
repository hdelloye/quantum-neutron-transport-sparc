# Qollab runtime findings (Phase 1 smoke test)

## Static facts (read from Qollab's runtime code, 2026-10-10)
- Pyodide v314.0.7 (Python 3.14.2, numpy 2.4.6, scipy 1.18.0, matplotlib 3.10.8 in its lockfile)
- Qollab /py index: qiskit 2.5.2 (only wasm build), qiskit-ionq 1.0.2, qiskit-aer 0.17.2
- backend preamble: built-in = BasicSimulator(); IonQ remote sim = IonQProvider("STUB").get_backend("simulator") + set_options(noise_model="<qpu>")
- qiskit_ionq installed only when an IonQ backend is selected; qiskit_aer only when an IBM noise model is selected
- main(...) is appended with positional form values; floats can arrive as ints
- One IonQ job per run (client-enforced); 403 → "anonymous user" message; proxy rejects oversized request bodies
- One circuit per IonQ job (server-enforced, observed 2026-10-10): Qollab's IonQ path accepts only job type `ionq.circuit.v1`; a circuit list (`ionq.multi-circuit.v1`) is rejected with HTTP 400 (runs R4-R6 on the old bundle)
- anon_enabled = true on 2026-10-10 (GET https://api.qollab.xyz/api/ionq/backends/simulator/cost)
- Re-uploading into an existing project skips README.md, so the write-up only updates by pasting README.md into the Project Card or by creating a new project from the archive (Pitfall 8)
- qiskit is imported by Qollab's preamble before main.py runs, so its import time shows up as the "initializing runtime" phase, not in wall_clock_s (Pitfall 10)

### What the ideal_mode values test
- `none`: keeps the noise model chosen in the Select QPU dialog (e.g. forte-1); counts are noisy.
- `kwarg`: sends `noise_model="ideal"` as a `backend.run` argument; if accepted, the counts are exact `round(p*shots)` with no shot noise.
- `set_options`: sets `backend.set_options(noise_model="ideal")` before the run; if accepted, the counts are sampled client-side with real shot statistics.
- The built-in BasicSimulator ignores the kwarg with a `UserWarning` and rejects `set_options` with an `AttributeError`, so `run_toy` applies both only on IonQ.

## Conclusions for later phases
- noise_model="ideal" via kwarg: ACCEPTED (R5, new bundle: `accepted: true`, counts `{"000000": 100, "111111": 100}`, noise_verdict "ideal, exact round(p*shots) (no shot noise)"). The counts are exact `round(p*shots)` with NO shot noise, so they must never be presented or used as sampled statistics. The old-bundle R5 failure was the multi-circuit job type, not the kwarg.
- noise_model="ideal" via set_options: ACCEPTED (R6, new bundle: `accepted: true`, counts `{"000000": 109, "111111": 91}`, noise_verdict "ideal, sampled"). Real shot statistics.
- noise_model none (dialog's forte-1 model): ACCEPTED and noisy (R4, new bundle: ghz_off_ideal_fraction 0.045 on 200 shots, 9 off-ideal outcomes).
- Phase 4 IonQ path should use: `backend.set_options(noise_model="ideal")` (set_options sampled) for ideal IonQ cloud runs with real shot statistics, and `none` (forte-1) for the honest noisy comparison. Never use the kwarg path for statistics.
- One circuit per IonQ Run (BLOCKER for the research plan): Qollab's IonQ proxy accepts only `ionq.circuit.v1`, so one job carries one circuit; with one job per Run (client-enforced), an IonQ Run on Qollab can execute exactly ONE circuit. The research assumption "the whole MLAE estimate is one multi-circuit job" is FALSE on Qollab. Phase 4 must redesign the IonQ path, for example one Run per Grover power (the judge runs main() once per power, results combined offline), or IonQ used only as a single-circuit execution proof of one `A Q^k` circuit while the MLAE curve comes from local and Built-in runs. The Built-in simulator is unaffected (several jobs and lists are fine locally).
- Logged-out runs: the published project runs start-to-finish on the Built-in simulator from an incognito window (R7: `SMOKE TEST PASSED`, wall_clock_s 0.081). Anonymous IonQ jobs are REFUSED by Qollab before running (R8: "credits apply, you need to sign in", Hippolyte's paraphrase, no report printed), even though the cost endpoint reported `{"cost":"0","anon_enabled":true}` at 14:51 and 15:24 ET. This is a server-side policy blocker for the logged-out IonQ half of criterion 1, not a code failure; the judged path (Built-in simulator) passes logged out, and signed-in IonQ runs pass.
- Runtime versions (every report): Python 3.14.2 (platform emscripten, Pyodide 314.0.7), numpy 2.4.6, scipy 1.18.0, qiskit 2.5.2, qiskit_ionq 1.0.2 when an IonQ backend is selected ("not importable" in a fresh session on the Built-in path; it stays importable for the rest of a session once an IonQ run has loaded it). The data file loaded by literal path.
- Timing: an IonQ Forte 1 job takes ~11.5 s round trip (run_s 11.435-11.587 for a 6-qubit GHZ, 200 shots); the console header showed 13.3-13.4 s per IonQ run. A Built-in run finishes in under 0.5 s of wall_clock_s (0.081-0.346) with a ~1.7 s console header.
- Live-run budget in Pyodide (Phase 6 quick mode): the 12-qubit depth-20 perf probe (220 CX, 1000 shots) ran in 0.037-0.046 s against 0.021 s native, so Pyodide is ~2x slower than native here. 16 and 20 qubits were not measured (R2/R3 not run); scaling the native 0.338 s / 6.486 s by ~2x suggests ~0.7 s at 16 and ~13 s at 20 qubits for one depth-20 circuit. Measure before relying on 20 qubits.
- Run settings form: showed all four fields (Shots, Ghz Qubits, Ideal Mode, Perf Qubits).
- Seconds to first output: not stopwatch-timed; the console header showed 1.7 s for R1 and R7.
- Published URL: https://qollab.xyz/u/hdelloye/quantum-neutron-transport-spar   (version v1.0, public and default; the plan's name v0.0-smoke was not used; Hippolyte chose v1.0)
- Before the final publish (Phase 6): re-run the built-in smoke test, re-check the qiskit version in https://qollab.xyz/py/index.json and re-check the anon_enabled flag.

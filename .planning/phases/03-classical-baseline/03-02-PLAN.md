## Decisions this plan implements

- **PD-08 (from 03-01; `costly`)**: every uniform comes from the injected source through `draw`; `as_source` is the only Generator constructor.
- **PD-10 (locked, research)**: the lattice engine is sequential conditional sampling of the four registers from the frozen tables, never a categorical draw over the 2^11 enumeration (that would be the exact solver in disguise and make convergence a tautology). One flight per history (WR-08): the tables assume the scatter site lies on the beam line, true only for the first collision of the pencil beam. The bit layout constants come from `exact.py`. Rows of scattered-and-escaped histories are sampled from `back_exit_rows[col, phi]` by inverse CDF scaled by that row's own total (`cumsum[..., -1]`, equal to `flight[col, phi, BACK]` within 1.2e-15), so a uniform below 1 can never land past the last positive-mass row; the index is clamped to ny - 1 as a second guard.
- **PD-11 (from 03-01)**: compare sums only (T1, the row histogram, the bit-string distribution against the enumeration); fixed seeds, |z| < 4, chi2 < dof + 5 sqrt(2 dof).
- **PD-12 (from 03-01)**: reproducibility = same source state, n, chunk, numpy version, platform; documented draw order.
- **PD-13 (locked, orchestrator)**: Phase 5 hooks are explicit artifacts: `checkpoints=` gives cumulative transmitted counts at several N from one run without storing per-history flags; `sample_exit_rows(k, bitstrings, source)` is public and shared with the engine; `LatticeResult` carries SEs; the classical cost is N = histories (one k = 0 application of A each), exposed as `LatticeResult.cost`.
- **PD-14 (from 03-01) and Open Question 1 (resolved)**: `kernels.py` is not edited in this phase because Phase 4 executes against it in parallel; the WR-08 caveat goes into the `mc_lattice` module docstring, and the `kernels.py`/PHYSICS.md docstring fixes (WR-07, WR-08) are left for a quick task after Phase 4.

## Interfaces used directly (all frozen; read, never edit)

- `neutron_qae.mc_lattice.run_lattice(k, n, source=None, *, chunk=1 << 16, return_bitstrings=False, checkpoints=())` returns `LatticeResult`; `prefix_estimates()` returns `(Ns, means, ses)`. `checkpoints` must be a tuple of ints in [1, n] (03-REVIEW IN-01: an int raises TypeError). A checkpoint prefix is not the same sample as a standalone run of that size (IN-02); the per-run Wald SE is 0 at small N (IN-03), so plots use RMSE over repetitions, never per-run SEs.
- `neutron_qae.oracle.make_problem(model="Q1", kernels=None)` returns `OracleProblem` with `A`, `flag`, `p` (contract-checked flag probability), `reference` (exact T1), `theta`, `kernels`.
- `neutron_qae.runners.AnalyticRunner(p, rng)`: `rng` goes through `np.random.default_rng`, so a `SeedSequence` child is accepted; one `rng.binomial(shots, sin^2((2k + 1) theta))` per k in input order. `BackendRunner(backend, problem, measure="flag")` with `.circuits(ks)` returning cached, once-transpiled circuits (1 classical bit named flag). `runners.load_ionq_records()` and `runners.ionq_estimate(records)` read `data/ionq_runs.json` relative to the working directory.
- `neutron_qae.mlae`: `estimate(records) -> MLAEResult` (`a_hat`, `se`, `n_A`), `exponential_schedule(M) = [0, 1, 2, 4, ..., 2^(M-2)]` (prefix-closed: the first M entries of `exponential_schedule(11)` are `exponential_schedule(M)`), `n_applications(records)`, `PowerResult(k, shots, hits, source="")`. 04-REVIEW WR-05: `se` collapses to about 0 at a in {0, 1}; never use it for z-scores in sweeps (errors are measured against the exact T1).
- `tests/compliance_checks.reachable_modules(ROOT)` and `test_every_data_file_is_referenced_by_literal_path`: every file on disk under data/ (rglob, tracked or not) must appear as a double-quoted literal `"data/<name>"` in a module reachable from main.py.
